本文档是规划方案，不改动现有任何代码。现有 docs/memoline-planning.html 定义的产品基线保持不变， 本规划在其之上叠加「知识库」能力。配套一个纯静态演示页 kb-demo.html（内置 mock 数据，双击即可预览）。

① 能不能做成知识库？—— 能，而且底子很好

知识库的本质是四件事：有条目的记录、有条目间的关系、能聚合、能检索。对照现有系统：

知识库要素现有系统对应物缺口
知识条目 events 表：时间、地点、描述、标签、event_type（记事/假设/待办/结论） 已有。事件类型天然区分了「事实 / 推断 / 行动 / 定论」，比一般笔记软件更贴近知识管理
证据与素材 event_media（图文视频）、event_chat_records（聊天记录） 已有，知识条目可直接挂证据
条目间关系 event_links：引用 / 因果 / 反驳，双向查询 关系类型偏少，且还没有「关系强度/置信度」概念
聚合（主题） tags 标签（松散、平铺） 主要缺口：标签不是主题，没有主题页、没有跨事件汇总叙述
检索 关键词 LIKE 模糊匹配（描述/地点） 无全文索引、无相关性排序、无分词
沉淀产物 analysis_reports：AI 复盘报告（摘要/时间线/疑点/证据分类） 报告是一次性产物，没有回流成可维护的知识条目
结论：系统已经具备知识库 70% 的骨架（条目、关系、证据、AI 分析）， 只需补上「主题聚合层 + 全文检索 + 图谱呈现」三块，即可从「时间线」升级为「时间线 × 知识库」双视图产品。

② 设计思路（核心原则）

双视图，不推翻时间线

时间线仍是录入与浏览的主轴；知识库是事件之上的只读聚合层 + 轻编辑层（主题页可补充人工总结）。 所有知识条目仍来自 events，不新增平行数据孤岛。

主题是「视图」不是「文件夹」

一个事件可属于多个主题（多标签聚合 + AI 归类），避免传统文件夹的二选一困境。 主题支持手动创建与 AI 自动聚类两条来源，手动优先。

AI 负责沉淀，人负责确认

大模型把复盘报告、事件链提炼成主题综述、关键结论、待验证假设； 生成的知识内容带 ai_generated 标记与来源事件引用，用户可编辑、采纳或丢弃。

检索用 SQLite 原生能力

用 FTS5 虚拟表做全文检索（支持中文 trigram 分词），零额外依赖、与现有便携 Python + SQLite 架构完全兼容， 不引入 Elasticsearch / 向量库这类重组件。

③ 功能清单（分期）

M1 · 知识库雏形

主题聚合

  • 主题（topic）数据表 + 事件多对多关联
  • 主题列表页：按主题浏览，显示事件数 / 类型分布 / 时间跨度
  • 主题详情页：综述 + 时间线子集 + 结论/假设高亮 + 关联证据
  • 标签 → 主题的一键升级为手动归类
  • 现有搜索升级 FTS5 全文检索（描述/聊天/地点，带高亮）
M2 · 关系可视化

知识图谱

  • 事件关系图：节点=事件（按类型着色），边=引用/因果/反驳
  • 以主题为中心的 ego 图（只看某主题内的关联网络）
  • 孤立事件检测（没有任何 link 的事件提示补关联）
  • 关系类型扩展：支持 / 派生 / 疑似相关，新增置信度字段
  • 节点点击直达事件详情，图可导出 PNG
M3 · 知识沉淀

AI 知识库化

  • 一键把复盘报告沉淀为主题综述（可编辑）
  • AI 自动聚类建议主题（对未归类事件批量推荐）
  • 结论演进链：同一假设被后续事件支持/反驳的谱系图
  • 知识问答：对某主题提问，AI 基于主题内事件回答并引用
  • 导出：主题页导出 Markdown / PDF 知识手册
功能分期优先级说明
主题表 + 事件-主题关联M1P0知识库的骨架，其余功能都依赖它
主题列表 / 详情页M1P0新页面 kb.html（列表）+ topic.html（详情）
FTS5 全文搜索M1P0trigram 分词兼容中文；触发器同步索引
事件关系图谱页M2P1前端用 vis-network 或自绘 canvas 力导向图
主题 ego 图 / 孤立事件M2P1图谱页的过滤维度
关系类型扩展 + 置信度M2P2沿用 M1.0.4 已上线的 event_links 增量 ALTER
报告 → 主题综述沉淀M3P1复用现有 analysis 管线的输出结构
AI 自动聚类建议M3P2把未归类事件标题+摘要交给 LLM 聚类
主题问答（带引用）M3P2RAG 简化版：主题内事件全文塞进上下文
知识手册导出M3P2Markdown 优先，PDF 复用报告导出通道

⑤ 数据模型扩展（SQLite）

新增：主题表与关联表

表字段说明
kb_topics id, name, slug, summary, icon, color, source(manual/ai), created_at, updated_at 主题条目本身；summary 存 AI 生成或人工编辑的综述（Markdown）
kb_topic_events topic_id, event_id, added_by(manual/ai), confidence, created_at 事件 ↔ 主题 多对多；AI 归类带置信度，人工加入视为 1.0
events_fts（FTS5 虚拟表） title? description, location, tokenizer=trigram 全文索引；由 events 上的 INSERT/UPDATE/DELETE 触发器同步
chat_records_fts（可选，M1 内） 同上，索引聊天记录 content 让「搜一句话」也能命中所属事件

现有表增量变更（幂等 ALTER，沿用 M1.0.4 的补列模式）

  • event_links 增列：confidence REAL（置信度 0~1，默认 1）、source(manual/ai)。
  • 关系枚举扩展（代码层）：引用 / 因果 / 反驳 → 追加 支持 / 派生 / 疑似相关。
  • analysis_reports 增列：topic_id（报告沉淀到哪个主题，可空）。
事件本体不加「主题」列——主题关系全部放在中间表，保持 events 表简单，也方便 AI 归类反复重跑而不污染原始数据。

⑥ API 设计（草案）

接口方法说明
/api/kb/topicsGET / POST主题列表（含事件数、类型分布、时间跨度）/ 新建主题
/api/kb/topics/{id}GET / PATCH / DELETE主题详情（综述 + 事件摘要）/ 改名改综述 / 删除（不删事件）
/api/kb/topics/{id}/eventsPOST / DELETE事件加入 / 移出主题
/api/kb/graphGET图谱数据：?topicId=&depth=&types= 返回 nodes + links，M2
/api/kb/searchGET全文搜索：?q=&scope=events,chat&types=&tags=，返回带 <mark> 高亮片段与 bm25 排序
/api/kb/topics/suggestPOSTAI 聚类建议：返回未归类事件的建议主题组，M3

/api/kb/topics/{id}/askPOST主题内问答，回答带来源事件引用，M3
/api/kb/topics/{id}/exportGET主题知识手册导出 ?format=md|pdf，M3

⑦ 技术要点与选型

中文全文检索

  • SQLite FTS5 的 trigram tokenizer（Python 3.13 内置 sqlite3 已可用，需 SQLITE_FTS5_TRIGRAM，实测标准发行版支持）。
  • 不可用时降级：jieba 分词 + 普通索引表（仍零外部服务）。
  • 排序用内置 bm25()；片段高亮用 snippet()。

图谱渲染

  • 前端零构建约束下，优先 canvas 自绘力导向（约 200 行）或 vis-network CDN。
  • 首期限定节点数 ≤ 300（超出按主题采样），避免卡顿。
  • 布局结果可缓存到 localStorage 之外——注意本项目 artifact 规则：用内存变量，不用浏览器存储。

AI 归类与综述

  • 沿用现有 OpenAI 兼容通道与 mock 降级机制。
  • 聚类建议输出 JSON schema 校验（复用 ai_report_parser 的解析套路）。
  • 所有 AI 写入均落 source='ai' + 置信度，人工操作可覆盖。

迁移与兼容

  • 建表 / 补列全部幂等，旧 data/app.db 直接开库升级，与 event_type 补列同一模式。
  • FTS 虚拟表首次创建时用 INSERT INTO … SELECT 全量回填一次。
  • 知识库路由独立成 routers/kb.py，不侵入 events 现有逻辑。
风险：AI 自动归类可能错挂主题 → 缓解：AI 归类默认进入「待确认」状态，主题页显式区分「已确认 / 待确认」两栏，用户批量确认后才计入综述。

⑧ 路线图

M1 主题聚合 + 全文搜索（1~1.5 周）

kb_topics 建表、主题列表/详情页、事件「加入主题」、FTS5 搜索升级。做完即达到演示页「主题聚合」「知识搜索」两个视图的效果。

M2 知识图谱（1 周）

图谱页、主题 ego 图、关系类型与置信度扩展、孤立事件提示。达到演示页「知识图谱」视图的效果。

M3 AI 沉淀与问答（1~2 周）

报告→综述沉淀、AI 聚类建议、主题问答、知识手册导出。达到演示页「Wiki 文档」视图的完整度（M1 先做人工编辑版综述）。

每个里程碑都保持「拷目录即运行」的便携性：不新增任何需要安装的服务端组件。
