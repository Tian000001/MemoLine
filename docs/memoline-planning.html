① 项目定位

一个时序事件归档平台：按时间点记录事件、地点、文字描述，支持上传照片 / 视频、导入聊天记录，自动生成可视化时间线；最后调用大模型对整条事件链做梳理、摘要、关系分析、疑点提炼。

适用场景：事件复盘、取证整理、项目纪实、个人大事记。首版定位 本地单机版，数据存本机、无需登录；模型调用做成可插拔接口，先留位、后续填 key 即生效。

② 设计思路（核心原则）

1 · 事件即原子

最小记录单位是一个"事件"：时间 + 地点 + 类型 + 标题 + 正文 + 标签。媒体、聊天、关联都挂在事件上，互不孤立。

2 · 时间轴为主线

首页一条可上下滑动的时间轴。支持列表视图切换、按类型/标签/地点/关键词筛选、顶部时间标尺缩放。

3 · 多模态证据挂载

照片/视频本地存文件、DB 存路径；聊天粘贴文本 / 传截图 / 传导出 txt，解析成结构化片段附在事件下。

4 · 关联而非堆叠

事件间可建立"引用 / 因果 / 反驳"关系，形成网络。复盘与疑点识别据此理清来龙去脉。

5 · 事实与猜测分开

事件带轻量 type（记事/假设/待办/结论）。复盘时模型能区分"记录的事实"与"当事人的猜测"，疑点识别才准。

6 · 先记录、后整理

记录门槛极低（一句话也行），整理交给模型。降低"写日记"的心理负担，鼓励随手记。

v0.2 已锁定设计决策（来自评审微调）
  • 时间线方向：首页用纵向时间轴 + 顶部时间标尺；横向时间轴视觉好但事件多时拥挤，放二期做缩略概览。
  • 事件 type 字段：录入保留轻量 type（记事/假设/待办/结论，默认记事），不增加负担。
  • 事件关联提进 MVP：至少支持手动引用/因果两条事件，供疑点识别使用。
  • 聊天导入 / 视频 → 二期：OCR 截图识别是重活（需接 OCR 服务），谨慎后置；二期先做粘贴文本 + 微信/txt 导出解析。
  • 分析先 mock：MVP 分析走 /analyze 占位，核心闭环是 录→存→看时间线；真模型放第二阶段填 key。
  • Context Assembler：后端单列"上下文拼接"模块，分析质量的关键（见 ⑥）。

③ 功能清单（分期）

首版 MVP（先做这些 · v0.2 锁定）

  • MVP 新建 / 编辑 / 删除事件：时间(精确到时分)、地点(手动输入)、类型(记事/假设/待办/结论，默认记事)、标题、正文、标签
  • MVP 首页：纵向时间轴 + 顶部时间标尺，可切换列表视图；筛选（类型 / 标签 / 关键词）
  • MVP 图片上传 + 缩略图（本地存储，DB 存路径）
  • MVP 事件详情页：完整文字、地图点位(手动)、图片预览、关联事件
  • MVP 事件间轻量关联（手动引用 / 因果）
  • MVP 分析面板：选范围 → 选模板(摘要/人物时间/疑点) → 调 /analyze（先 mock 占位）→ 结果展示 + 复制

二期（Phase 2）

  • LATER 短视频上传与预览 / 转码
  • LATER 聊天导入：粘贴文本 + 微信/txt 导出解析（OCR 截图识别谨慎后置）
  • LATER 接真实模型：填 API key / 本地 Ollama，分析可追问、可保存
  • LATER 横向缩略时间轴、地图选点、日历视图

更后期

  • LATER 全文检索 + 语义检索（向量库）
  • LATER 导出报告 Markdown / PDF、时间线截图
  • LATER 云端同步 + 多成员协作（需账号体系）

⑤ 数据模型（SQLite）

表关键字段说明
eventsid, datetime, location, type, title, content, tags, created_at事件本体。type ∈ {记事, 假设, 待办, 结论}
mediaid, event_id, kind(photo/video), path, caption, created_at媒体文件存本地目录，DB 仅存路径
chatsid, event_id, source, raw_text, parsed_json, created_at导入的聊天；parsed_json 存结构化片段（二期）
linksid, from_event, to_event, relationrelation ∈ {reference, causal, refute}
analysesid, scope, prompt, result, model, created_at复盘记录，可回看/追问

文件存储：./data/media/ 下按年月分目录；DB 在 ./data/memoline.db。本地单机，无云端。

⑥ 技术架构

前端

React 或 Vue3 + Vite + Tailwind。时间线自绘组件，图表轻量。（build 时定一个）

后端

Python FastAPI。事件/媒体/聊天/分析 REST 接口；静态文件服务媒体。

存储

SQLite + 本地文件系统。零外部依赖，开箱即跑。

模型接口（先留位，后接）

后端 POST /analyze 先返回 mock 结构；约定好入参（事件+媒体+聊天的上下文拼接）与出参（markdown 报告）。之后填 API key 或换本地模型，前端无需改动。

关键模块 · Context Assembler：分析前由后端把"选中事件 + 媒体说明(caption) + 聊天解析(parsed_json)"拼成结构化 prompt（含时间 / 地点 / type / 关联），再送模型。这是复盘质量的关键，且独立于具体模型供应商——换 OpenAI / 通义 / 豆包只改一处适配。

⑧ 路线图

  • Phase 1 · MVP（本次）：事件 CRUD(含 type) + 纵向时间轴/列表 + 图片缩略图 + 轻量关联 + 分析面板(mock 占位)，SQLite + 本地 media，本地跑通。
  • Phase 2：短视频、聊天导入(文本/导出解析)、接真实模型(填 key/Ollama)、横向缩略时间轴、地图选点。
  • Phase 3：语义检索、OCR 截图识别、证据自动归类增强。
  • Phase 4：报告导出(MD/PDF)、时间线截图、可选云端同步 + 多成员协作。
